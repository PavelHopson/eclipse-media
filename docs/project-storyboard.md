# Сценарий проекта и передача в монтаж

## Основной путь

1. План / Разбор субтитров: выбрать фрагмент, написать тезис, нажать «Создать сцену».
2. Сценарий: дополнить название, длительность, музыку (или «Тишина»), действие и камеру. Незавершённые поля отмечены; черновик сохраняет их как есть.
3. Менять порядок кнопками «Выше» и «Ниже». Убранную сцену можно вернуть до ухода из раздела. Сцены из бит-карты добавляются отдельной редактируемой копией и не меняют оригинал.
4. «В безопасный монтаж» передаёт снимок одной заполненной сцены. Ни файл, ни задача не запускаются автоматически.
5. На сайте: подтвердить право просмотра, выбрать локальный MP4, проверить реальные кадры и границы. На desktop: явно выбрать ранее подготовленный MP4, проверить фиксированный план, подтвердить право обработки и нажать создание MP4.

## Контракт

frontend/src/services/projectStoryboardContract.ts. До 24 сцен, до 4 тезисов на сцену, уникальные UUID, длительность от 0 (незаполнено) до 60 секунд. Название 80 символов, музыка 512, действие/камера по 400. Тезис сохраняет fileName, sha256 субтитров, cueId, start/end, excerpt, claim, status, evidenceUrl, videoUrl. Известные ключи строго проверяются; дополнительные команды/поля и управляющие символы отклоняются.

Связь является снимком. Последующее изменение или удаление исходного разбора не переписывает сцену, а показывает предупреждение. Статус «проверено» означает только решение автора заметки, не автоматическую проверку факта. URL не загружаются. Активная ссылка на момент строится только для разрешённого YouTube video ID. Остальные введённые адреса отображаются текстом.

Сценарий хранится в необязательном beats.storyboard и наследует автосохранение бит-карты. Повторный анализ музыки сценарий не удаляет. Копия, импорт, экспорт, переключение и корзина включают сценарий. Старые draft v1 без поля остаются валидны. Backup v2 нельзя выдавать за v1; старая версия приложения отклонит его, а не проигнорирует сцены.

## Безопасные границы

- Таймкоды цитат не становятся границами произвольного видео. В монтаже по умолчанию предлагается начало выбранного файла и длительность сцены; соответствие и границы проверяет человек.
- Локальный браузерный просмотр: MP4 до 60 МиБ / 5 минут, проверка расширения, размера, ftyp, декодируемых metadata, SHA-256. Сырой файл и blob URL не сохраняются и не отправляются. Неверный следующий файл не заменяет предыдущий успешный. При уходе blob URL освобождается; поздний результат не применяется.
- Серверный web runtime остаётся preview-only. Нет произвольных путей, upload endpoint, FFmpeg-команд или генераторов. Полный монтаж сцен, добавление музыки и эффектов не реализуются этим фиксированным trim-контуром.
- Desktop trim ограничен прежним профилем H.264/AAC/720p, серверной верификацией источника и одноразовым разрешением. Изменение границ сбрасывает подтверждение. Регистрация исходника больше не вызывается автоматически при открытии экрана.
- Снимок передачи исчезает при перезагрузке и не переносится в другой выбранный проект. Сам сценарий остаётся в проекте.

## Проверки

Unit: frontend/tests/local-projects.test.mjs, прежние local edit и portable-file tests. Browser: scripts/qa-storyboard.cjs, отдельный Edge, synthetic MP4, desktop 1440 и mobile 390/320, reduced motion, весь путь, отмена, неверный MP4, источник после изменения, backup v2, корзина, две вкладки. Все серверные мутации и сторонние запросы в web QA блокируются. Production mode проверяется по реальному capability GET, только локальный static preview использует fixture этого ответа.
